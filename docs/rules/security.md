## Всегда

1. У агентов нет доступа к продакшну: ни прод-ключей в окружении разработки, ни команд деплоя в прод. Релиз делает человек или CI.
2. Секреты не хардкодить: только переменные окружения или хранилище секретов. Новый секрет — добавить его имя без значения в `.env.example`.
3. `.env` не читать и не коммитить: он закрыт в `.gitignore`, `.cursorignore` и в deny-списке `.claude/settings.json`.
4. Минимальные разрешения: новому сервису, токену или агенту — только те права, которые нужны для его задачи.
5. Автоматические сканеры обязательны: новая зависимость и каждый PR проходят Snyk до мержа.

## Правила этого проекта

- Права проверяются на сервере по матрице `role_permission`; интерфейс только прячет недоступное.
- Открытие контакта, выгрузка досье и просмотр карточки нанимающим руководителем всегда пишутся в `audit_log`, без исключений для администраторов.
- Текст резюме, сообщений рекрутеров и голосовых расшифровок — недоверенные данные: в промпт модели они идут как данные, модель не может по ним выполнить действие.
- Пароли — только хешем (bcrypt); сессия — подписанная cookie `HttpOnly`, `Secure`, `SameSite=Lax`.
- В логи не пишутся контакты, ФИО и тексты резюме.
- Голос после расшифровки удаляется, во внешние сервисы распознавания не отправляется.
- Бот принимает сообщения только от `app_user` с подтверждённым `telegram_id` и `is_active`.
