## Именование

- Файлы Python: snake_case; модули пакета — по предметной области (`scoring.py`, `pipeline.py`, `exchange_1c.py`).
- Классы — PascalCase, функции и переменные — snake_case. Имена таблиц и полей — как в `schema_recruiting.sql`.
- Ветки и коммиты — по .workflow/WORKFLOW.md, раздел «Git».

## Куда класть новые файлы

- Новый модуль логики → `server/hr/`; эндпойнты API → `server/hr/api/`
- Изменение базы → новый файл `server/migrations/NNN_<что>.sql`, только добавляющий
- Тесты → `server/tests/test_<модуль>.py`; тест на сценарий спеки называется по сценарию
- Интерфейс → `server/web/`; бот → `bot/`; расшифровка голоса → `stt/`
- Документация фичи → docs/work/<slug>/

## Стиль кода

- Источник правды — `ruff` с настройками в `server/pyproject.toml`. Команда — в AGENTS.md, раздел HOW.
- Здесь только то, что линтер не проверяет:
  - Тексты для пользователя, комментарии и сообщения журнала — по-русски, без канцелярита.
  - SQL пишется явно, без ORM; параметры только через плейсхолдеры `%s`.
  - Пороги и сроки — из таблицы `settings`, не константами в коде.
  - Каждый выпуск обновляет справку «Как работает портал» в «Схеме» (`server/web/js/guide.js`) и мануалы (`Мануал_рекрутера.md`, `Мануал_руководителя.md` → docx): что умеет, правила, права ролей. Решение человека 2026-10-30.
  - Каждое изменение поведения системы (профиль, порог, вес, права) пишется в `agent_change`.
