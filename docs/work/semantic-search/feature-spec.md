## Зачем — главная сессия

Отдел персонала (Котенко А., 20.11.2026): подбор по профилю ищет только точные ключевые слова. Широкий профиль даёт
«дичь», точный — 0 резюме; по инженеру-электронику на hh ~1400 подходящих, у портала 61. Рекрутер ищет руками на hh.
Причины в коде: запрос к hh — название + первые 6 ключей (`server/hr/hh.py:207`), балл — буквальные совпадения ключей
(`server/hr/scoring.py:164`, `:216`), за сбор — не больше 5 страниц по 50 на должность (`server/migrations/001_core.sql:87`).
Результат: портал находит похожих по смыслу и другой терминологии, балл остаётся у кода и объясним (AD-2).
Мерило — оценка Анастасии по выдаче для инженера-электроника до и после обновления.

Роли — как сейчас: «рекрутер» — специалист отдела персонала с правом правки профилей.

### Синонимы

**S1: модель предлагает синонимы.** Дано: у профиля «Инженер-электроник» ключи «Altium», «схемотехника». Когда:
рекрутер нажимает «Предложить синонимы». Тогда: у каждого ключа — предложенные термины («P-CAD», «KiCad»;
«разработка схем»), рекрутер снимает лишние, дописывает свои и сохраняет. Ничего не сохраняется без кнопки.

**S2: правка сразу, с журналом.** Когда: рекрутер сохраняет синонимы. Тогда: они действуют без утверждения, в журнале
— кто, когда, было и стало; профиль пересчитывается в фоне.

**S3: откат.** Когда: рекрутер откатывает запись журнала о синонимах. Тогда: синонимы — как до правки, откат тоже в журнале.

**S4: модель недоступна или предел на сутки исчерпан.** Когда: «Предложить синонимы». Тогда: «Модель сейчас недоступна —
впишите синонимы сами» или «Предел запросов к модели на сегодня исчерпан»; вписать вручную можно всегда.

**S5: ключ засчитан по синониму.** Дано: в резюме «P-CAD», нет «Altium». Тогда: ключ «Altium» засчитан, в объяснении
«Altium ≈ P-CAD».

**S6: запрос к hh шире.** Тогда: в поиске hh по профилю — название, ключи и их синонимы. Профиль без синонимов ищется как раньше.

### Смысл

**S7: похожий по смыслу без тех же слов.** Дано: резюме описывает разработку плат и электроники другими словами, ключей
мало. Тогда: балл учитывает близость к профилю по смыслу; в объяснении «близко к профилю по смыслу: 0,82».

**S8: модель векторов недоступна.** Тогда: балл считается как без смысла, сбор не падает, в «Схеме» — предупреждение.

**S9: поиск в «Базе» по смыслу.** Когда: рекрутер вводит «разработчик печатных плат». Тогда: сверху — близкие по смыслу,
в том числе без этих слов в резюме.

**S10: первый пересчёт базы.** Дано: обновление поставлено. Тогда: векторы базы пересчитываются ночью по частям; до
пересчёта человек оценивается без смысла; в «Схеме» — сколько осталось.

### Нагрузка

**S11: полные резюме hh — не больше предела в сутки.** Дано: предел 300 (из 500 просмотров компании в сутки, 200 —
рекрутерам на сайте). Когда: сборы за сутки дошли до предела. Тогда: остальные подходящие ждут следующего дня, в
«Схеме» — «предел полных резюме на сегодня исчерпан».

**S12: Qwen — только по кнопке и в пределе.** Дано: модель подключена. Тогда: объяснения балла и черновики моделью
выключены, пока руководитель не включит их настройкой; все обращения к модели — в общем суточном пределе.
