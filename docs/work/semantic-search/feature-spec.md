## Зачем — главная сессия

Отдел персонала (Котенко А., 20.11.2026): подбор по профилю ищет только точные ключевые слова. Широкий профиль даёт «дичь», точный — 0 резюме; по инженеру-электронику на hh ~1400 подходящих, у портала 61. Рекрутер ищет руками на hh. Причины в коде: запрос к hh — название + первые 6 ключей (`server/hr/hh.py:207`), балл — буквальные совпадения ключей (`server/hr/scoring.py:164`, `:216`), за сбор — не больше 5 страниц по 50 на должность (`server/migrations/001_core.sql:87`). Результат: портал находит похожих по смыслу и другой терминологии, балл остаётся у кода и объясним (AD-2). Мерило — оценка Анастасии по выдаче для инженера-электроника до и после обновления.

## Поведение (BDD) — главная сессия

Роли — как сейчас: «рекрутер» — специалист отдела персонала с правом правки профилей.

### Синонимы
- **S1: модель предлагает синонимы.** Дано: у профиля «Инженер-электроник» ключи «Altium», «схемотехника». Когда: рекрутер нажимает «Предложить синонимы». Тогда: у каждого ключа — предложенные термины («P-CAD», «KiCad»; «разработка схем»), рекрутер снимает лишние, дописывает свои и сохраняет. Ничего не сохраняется без кнопки.
- **S2: правка сразу, с журналом.** Когда: рекрутер сохраняет синонимы. Тогда: они действуют без утверждения, в журнале — кто, когда, было и стало; профиль пересчитывается в фоне.
- **S3: откат.** Когда: рекрутер откатывает запись журнала о синонимах. Тогда: синонимы — как до правки, откат тоже в журнале.
- **S4: модель недоступна или предел на сутки исчерпан.** Когда: «Предложить синонимы». Тогда: «Модель сейчас недоступна — впишите синонимы сами» или «Предел запросов к модели на сегодня исчерпан»; вписать вручную можно всегда.
- **S5: ключ засчитан по синониму.** Дано: в резюме «P-CAD», нет «Altium». Тогда: ключ «Altium» засчитан, в объяснении «Altium ≈ P-CAD».
- **S6: запрос к hh шире.** Тогда: в поиске hh по профилю — название, ключи и их синонимы. Профиль без синонимов ищется как раньше.

### Смысл
- **S7: похожий по смыслу без тех же слов.** Дано: резюме описывает разработку плат и электроники другими словами, ключей мало. Тогда: балл учитывает близость к профилю по смыслу; в объяснении «близко к профилю по смыслу: 82 %».
- **S8: модель векторов недоступна.** Тогда: балл считается как без смысла, сбор не падает, в «Схеме» — предупреждение.
- **S9: поиск в «Базе» по смыслу.** Когда: рекрутер вводит «разработчик печатных плат». Тогда: сверху — близкие по смыслу, в том числе без этих слов в резюме.
- **S10: первый пересчёт базы.** Дано: обновление поставлено. Тогда: векторы базы пересчитываются ночью по частям; до пересчёта человек оценивается без смысла; в «Схеме» — сколько осталось.

### Нагрузка
- **S11: полные резюме hh — не больше предела в сутки.** Дано: предел 300 (из 500 просмотров компании в сутки, 200 — рекрутерам на сайте). Когда: сборы за сутки дошли до предела. Тогда: остальные подходящие ждут следующего дня, в «Схеме» — «предел полных резюме на сегодня исчерпан».
- **S12: Qwen — только по кнопке и в пределе.** Дано: модель подключена. Тогда: объяснения балла и черновики моделью выключены, пока руководитель не включит их настройкой; все обращения к модели — в общем суточном пределе.

### Синонимы (S1–S6)
**Хранение.** **A (рекомендую):** таблица `role_synonym (role_code, keyword)` по `role_profile.code` — переживает новые версии; цена: синонимы не версионируются, `match.profile_version` их не отражает, история — в `agent_change`. Отвергнут B — `synonyms jsonb` в `role_profile`: правка создаёт версию и ждёт утверждения (`profiles.py:120`), против «сразу, без утверждения».
- Читаются синонимы только ключей действующей версии. Утверждение версии без ключа (`profiles.approve`, `profiles.py:147`) удаляет его строки с записью в `agent_change` «ключ удалён в версии X». Ключ нормализуется: `lower`, «ё» → «е».
- Проверка при сохранении (по образцу `tweaks.clean`, `tweaks.py:33`): 2–60 знаков, без ссылок и `< > " ( ) !`; не совпадает с ключом и другим синонимом; не больше 10 на ключ; ключ есть в действующей версии.
- Журнал: `agent_change kind='synonyms'`; `before` — полный снимок `{"role_code", "synonyms": {ключ: [...]}}`, `after` — то же после правки + `profile_id` и `rollback_of`; `applied_by` — автор. Откат пишет `before` новым снимком, только для последней записи `synonyms` должности, иначе 409 (так требует UI). После сохранения и отката в фоне — `pipeline.rescore_profile` (`pipeline.py:373`), `tweaks.user_rescore` и пересчёт вектора профиля.

**Балл (S5)**, `_f_keywords`, подпись «совпало: схемотехника, Altium ≈ P-CAD»:
- ключ засчитан по самому ключу (`phrase_found`, без изменений) или любому синониму; знаменатель `need` — от числа ключей;
- синоним короче 5 знаков — только целым словом, иначе `p in hay` (`scoring.py:169`) найдёт «ПП» внутри любого слова;
- синонимы не применяются к `must_have`, `nice_to_have`, `stop_factors`; минус-поправка ключа (`scoring.py:106`) снимает ключ вместе с синонимами;
- `events_from_diff` (`pipeline.py:357`) получает ключи с синонимами: появление синонима — тоже новый навык.

- **Запрос к hh (S6).** Начало прежнее (название + первые 6 ключей), затем синонимы этих ключей по кругу (первый у каждого ключа, потом второй…), всего не больше `hh_query_max_terms` (20). Многословный термин — в кавычках, как сейчас (`hh.py:211`); кавычки и скобки отсеяны при сохранении, поэтому `OR`, `AND`, `NOT` во фразе — просто слова. Без синонимов — ровно прежние параметры (тест). Страниц столько же (`crawl_per_profile_pages`); больше претендентов на полное резюме держит предел S11. Предел длины `text` hh не указан (`docs/reference/hh-api.md:51`) — см. «Открытые вопросы».
- **Предложение модели (S1, S4).** Вход — только `{"title", "keywords"}` профиля. Ответ — ровно `{"synonyms": {ключ: [термины]}}`: неизвестные ключи отбрасываются, термины проходят проверку сохранения, не больше 8 на ключ; не прошёл — «модель ничего не предложила». Кэш — `ops.llm_cache` (`002_workplace.sql:43`, purpose `synonyms`, `person_id` NULL): повтор с теми же ключами модель не вызывает и предел не тратит.

### Нагрузка на модель (S12)
`llm.guarded_complete(conn_factory, purpose, messages, **kw)`: 1) флаг назначения — `synonyms` всегда, остальные при `llm_assist_enabled = true`; 2) `quota.take('llm_call', llm_calls_per_day)`; 3) `complete`. Ошибки — `LLMDisabled`, `LLMDailyLimit`, `LLMUnavailable`.
- На неё переводятся все вызовы `llm.complete`: `explain.py:80` (фоновое объяснение), `assist.py:64` (разбор в досье), `actions.py:107` (черновики), `learning.py:88`, `:218` (разбор замечаний, дайджест). Тест-замок: `llm.complete` вызывается только из `llm.py`, по образцу `routes_unscoped` (AD-7).
- Флаг выключен — всё по шаблону (AD-2); `explain_pending` сразу выходит с пометкой «объяснения моделью выключены». Часовой предел `llm_calls_per_hour` (`assist.py:28`) остаётся.
- Флаг правится без экрана: `python -m hr.cli setting set <key> <value> --by <login>` пишет `agent_change` с `after.setting` и `applied_by`, поэтому `ops.change_default` (`009_release.sql:48`) не перетрёт правку человека.

### Суточные пределы (S11, S12)
- `quota.take(conn_factory, key, cap) -> bool` — своя короткая транзакция, фиксируется до внешнего вызова: откат транзакции резюме не отменяет учёт списанного у hh просмотра. Атомарно: `INSERT … ON CONFLICT (day, key) DO UPDATE SET used = used + 1 WHERE used < cap RETURNING used`; `cap <= 0` — сразу `false`. Сутки — по Москве (`views.py:15`). Неудачный вызов единицу не возвращает — осторожный счёт: hh мог списать просмотр.
- Ключ `hh_full_resume` берётся перед каждым `GET /resumes/{id}` (`collect.py:59`, `:174`). Исчерпан — `full_left = 0`, в `stats.note` «предел полных резюме на сегодня исчерпан», обход выдачи продолжается, как при `ViewLimitExceeded` (`collect.py:60`). `collect_hh_daily` (`collect.py:202`) берёт меньшее из `views_left`, остатка предела и `count`; `hh_full_resume_per_run` остаётся пределом прогона.
- Открытие контакта рекрутером (`contact_hh.py:123`) в предел не входит: действие человека, резюме уже открыто. Обход начинается с должности `день года % N`, чтобы первые должности не забирали весь предел.

- Оценка: ~15 тыс. резюме × до 512 токенов на 8 ядрах — 1–3 часа, проверить замером; ресурсы — «Открытые вопросы».

**Признак `semantic` («Близость по смыслу»).**
- `scoring.score(..., semantic: float | None = None)` остаётся чистой; косинус считает вызывающий в SQL одним запросом на человека: `ops.profile_embedding` × `person_embedding` текущей модели.
- `ratio = clamp((cos − semantic_sim_floor) / (semantic_sim_full − semantic_sim_floor))`, умолчания 0,40 и 0,75, калибровка — на выдаче по инженеру-электронику; процент в подписи — `round(cos·100)`.
- Вес: `profile.weights["semantic"]`, иначе `semantic_weight_default` — **15**, как у «Совпадения должности» и меньше 25 у ключей, чтобы подгонкой текста нельзя было набрать балл одним смыслом; `0` выключает признак у профиля. `"semantic"` добавляется в `FEATURE_LABELS` (`scoring.py:13`) — его начнёт принимать `profiles._validate` (`profiles.py:90`).
- Нет вектора человека или профиля, или модель недоступна: `{"points": 0, "max": 0, "skipped": "no_vector" | "embed_down", "detail": …}` вне суммы весов — балл как без смысла (S8, S10); `template_explanation` такие признаки уже пропускает (`scoring.py:341`).

- **Вход в базу новых людей.** **B (рекомендую):** для полного резюме hh в «серой зоне» (балл без смысла не ниже `watch_threshold` минус максимум признака) вектор считается до транзакции резюме (`collect.py:67`), передаётся в `pipeline.process` и пишется в `person_embedding`; цена — не больше 300 вызовов в сутки (как полных резюме, S11), «Работа России» и файлы входят без смысла: их тысячи. Отвергнут A (смысл только у уже вошедших в базу): резюме, похожее лишь по смыслу, не пройдёт порог — S7 сработает только для вошедших по ключам.
- **Вектор профиля** — в `ops.profile_embedding`; текст: название, ключи, синонимы, тексты `must_have` и `nice_to_have`; пересчёт при смене `text_sha256` — при утверждении версии, правке и откате синонимов, ночью.
- **Ночной пересчёт (S10)** — задача `reembed_night`, блокировка `("embed",)`, ночью вне окна `collect_trudvsem` (`load_check.py:27`). Порядок: векторы профилей → люди без вектора текущей модели → устаревшие (`search.py:35`). Пачка — своя транзакция: векторы, затем `rescore_person` и `tweaks.rescore_person_all` по её людям. Остановка — в `embed_night_until` (`"06:30"` по Москве) или после трёх отказов подряд. Текущий досчёт в задаче `score` (`tasks.py:32`) — одна пачка, чтобы утром не занять процессор. Проверить в плане: пересчёт по векторам не создаёт сигналы (как `rescore_profile`).
- **Отказ (S8)** — `ops.service_health('embed')`: `down_since` ставится при первом отказе, сбрасывается при первом успехе; признак — `skipped: "embed_down"`, поиск — 503, как сейчас (`api/base.py:80`).
- **Поиск (S9).** Фильтр `embed_model = current` с HNSW (`schema_recruiting.sql:416`) при переходе может вернуть меньше 30 строк — `SET LOCAL hnsw.ef_search = 200` или `hnsw.iterative_scan` при pgvector ≥ 0.8 (версию проверить). Запрос — не длиннее 300 знаков.

## Безопасность — backend-architect

| Сервис | Что получает | Сеть |
|---|---|---|
| Qwen | только название и ключи профиля, данных людей нет | `http://10.20.10.6`, корпоративная сеть без TLS — допустимо: персональных данных в запросе нет |
| bge-m3 | тексты резюме — персональные данные | тот же сервер, только 127.0.0.1 (AD-6), во внешнюю сеть не ходит |

- Текст для вектора — `learning.strip_contacts` (`learning.py:54`) поверх `pipeline.person_text` (`pipeline.py:207`): в «о себе» бывают телефоны и почта. ФИО в `person_text` нет, `label` не используется.
- Новых секретов нет (локальным сервисам ключ не нужен); в `.env.example` — только имена `EMBED_TIMEOUT_S`, `EMBED_BASE_URL`, `EMBED_MODEL` без значений.
- В логи не пишутся: запрос из «Базы» (в нём может быть имя), ответ модели (`llm.py:3`), тексты резюме.
- Права: чтение синонимов — со скоупом AD-7 (вне скоупа 404), правка и откат — `profile.synonyms` по `role_permission`; тест `routes_unscoped` покрывает четыре новых маршрута. Синонимы — не персональные данные: хватает `agent_change`, `audit_log` не нужен.
- Нагрузка: «Предложить» — суточный предел и кэш; `/api/search` — запрос ≤ 300 знаков; `llm_assist_enabled` — только из CLI на сервере, с записью в `agent_change`.
- Синонимы и предложения модели интерфейс выводит только как текст (`textContent`), без HTML.
