## Зачем — главная сессия

Конвейер `core` уже наполняет базу (2026-10-29: 199 резюме hh, 55 карточек), но смотреть её можно только из терминала. Нужно рабочее место в браузере по прототипу `Рабочее_место_рекрутера.html` (эталон экранов и текстов, ТЗ 10). В нём человек видит кандидатов с фото и разбором, принимает решения, ведёт вакансии и профили и учит агента. Действия с людьми агент только готовит, решает человек.

### Вход и права

**S1: вход по паролю.** Дано: временная учётная запись, созданная командой `hr.cli`. Когда: пользователь вводит логин и пароль на localhost:8000. Тогда: открывается «Сегодня», сессия — подписанная cookie `HttpOnly`, `SameSite=Lax`. Пароль хранится только хешем.
**S2: без входа ничего не видно.** Дано: нет сессии. Когда: запрос к любой странице или `/api/*`. Тогда: страница входа или 401. Данные о людях не уходят.
**S3: права проверяет сервер.** Дано: учётная запись с ролью без права (например, `recruiter` без `profile.approve`). Когда: запрос мимо интерфейса. Тогда: 403, данные не меняются (32, 48).

### «Сегодня»

**S4: утренний экран.** Дано: есть новые сигналы и действия, ждущие подтверждения. Когда: пользователь открывает «Сегодня». Тогда: видны сигналы «обратите внимание» (не больше `daily_cards_limit`), очередь подтверждений и зависшие кандидаты. Каждая карточка: фото, имя (если hh его отдал, иначе ярлык), балл, одна строка разбора.
**S5: пустой день.** Дано: сигналов и действий нет. Тогда: «Сегодня всё разобрано» и ссылка на «Базу».

### Досье

**S6: досье.** Когда: пользователь открывает человека. Тогда: фото, имя или ярлык, балл по каждому профилю с разбором «сколько из скольких», резюме по версиям, места работы, навыки, следы в сети с уверенностью, лента изменений, история решений.
**S7: разбор моделью по требованию.** Дано: модель настроена, разбора моделью для этой версии резюме и профиля ещё нет. Когда: досье открыто. Тогда: разбор и вопросы к собеседованию пишет модель, результат сохраняется. Повторное открытие запросов к модели не делает. В модель не уходят имя, контакты и фото.
**S8: модель недоступна или пакет кончился.** Тогда: разбор по шаблону и пометка «разбор по шаблону». Досье открывается без ошибки.
**S9: фото.** Дано: в ответе hh есть ссылка на фото. Тогда: система скачивает фото один раз, сжимает до 10 КБ и хранит у себя. Ссылка не работает или фото нет — заглушка с инициалами или значком.
**S10: выгрузка досье** (25, 30). Когда: «Выгрузить» → Word или PDF. Тогда: файл с разделами из пункта 30, запись в `dossier_export` и `audit_log` с автором и временем.

### Решения по человеку

**S11: в работу.** Когда: «В работу» по вакансии. Тогда: человек становится кандидатом в воронке этой вакансии на этапе «Отобран агентом», основание обработки записано, запись в `status_history`.
**S12: отложить или «не наш»** (18). Когда: решение с комментарием от 200 знаков. Тогда: решение сохранено в `decision_log`, «отложить» ставит напоминание через три месяца, «не наш» убирает человека из выдачи по профилю.
**S13: короткий комментарий** (18). Комментарий короче 200 знаков: кнопка «Сохранить» неактивна, прямой запрос к API → 422, вставка мимо API отбивается проверкой СУБД.
**S14: вести особо** (14). Когда: «Вести особо». Тогда: порог для этого человека отменяется, сигнал приходит на любое изменение его резюме.
**S15: подтвердить профиль в сети.** Когда: подтверждает вероятный профиль. Тогда: `confirmed`, профиль учитывается в разборе.

### Контакт и действия

**S16: открытие контакта** (11). Дано: человек с hh, контакт не открыт. Когда: «Открыть контакт» → подтверждение «спишется один контакт hh». Тогда: система получает контакт у hh, сохраняет его в зоне кандидата, показывает в досье. Запись в `audit_log` с именем пользователя.
**S17: контакт скрыт или лимит.** Дано: hh скрыл контакт (`hidden_fields`) или лимит исчерпан. Тогда: предупреждение до списания (скрыт) или понятная причина (лимит). Ничего не списано повторно.
**S18: черновик письма** (9, 10). Когда: «Написать» → агент готовит черновик (модель или шаблон) → действие в очереди. Пользователь «Одобряет»: текст копируется, статус кандидата «Написали», запись в `status_history`. «Отклоняет» с причиной: причина в `action_queue.decline_reason`.

### База и поиск

**S19: база** (22). Тогда: таблица всех карточек с сортировкой по любой колонке и фильтрами по значениям (подразделение, город, должность, балл, где числится, источник).
**S20: поиск по смыслу.** Когда: запрос словами («схемотехник Altium»). Тогда: список по близости.

### Вакансии и воронка

**S21: новая вакансия.** Когда: пользователь заводит вакансию по профилю. Тогда: вакансия `origin = manual` в списке «Открытые».
**S22: показать подходящих** (22). Тогда: база с фильтрами вакансии и сортировкой по убыванию балла.
**S23: закрыть вакансию** (23, 24). Комментарий от 200 знаков обязателен (иначе как в S13). После закрытия сбор по должности продолжается (`keep_sourcing = true`).
**S24: воронка.** Когда: вкладка «Воронка» по вакансии. Тогда: этапы с людьми и средним временем на этапе. Карточка открывает досье, перевод между этапами пишется в `status_history`.

### Профили должностей

**S25: список профилей.** Тогда: все профили с поиском и статусом версии («утверждена», «ждёт утверждения», «черновик»).
**S26: правка создаёт версию** (21). Когда: пользователь меняет профиль. Тогда: новая версия «ждёт утверждения», выдача считается по прежней. Предпросмотр показывает, сколько людей пройдёт порог при новых настройках.
**S27: утверждение** (32). Когда: роль с `profile.approve` утверждает. Тогда: версия действует, база пересчитывается (`rescore_profile`), запись в `agent_change`.
**S28: замена ДИ** (29). Когда: загружен новый файл должностной инструкции. Тогда: файл в хранилище, запись в `job_doc`, предложение правок профиля в очереди.

### Обучение агента, журнал и отчёт

**S29: чат обучения.** Когда: сообщение от 40 знаков. Тогда: в ленте, агент отвечает (модель или шаблон «записал, учту в сводке»). Короче 40 — не отправляется.
**S30: недельная сводка** (19). Дано: за неделю похожие сообщения. Когда: формируется сводка. Тогда: одно предложение с обоснованием, а не три.
**S31: решение по сводке** (20). Когда: руководитель «принимает» пункт. Тогда: при ночном применении изменение внесено, запись в `agent_change` с автором и датой. «Отклонить» — без изменений.
**S32: журнал изменений.** Тогда: все `agent_change` по времени: что, было → стало, кто.
**S33: отчёт за неделю** (26). Тогда: отчёт об изменениях на экране и кнопкой «Сформировать сейчас».

### Схема

**S34: схема работы агента.** Тогда: экран «Схема» как в прототипе, с живыми цифрами последнего прогона (`ops.job_run`).

### Ошибки

**S35: сервер недоступен или ошибка API.** Тогда: на экране понятное сообщение на русском, введённый текст комментария не теряется.

## Вне рамок — главная сессия

- Вход из 1С, несколько пользователей и роли по должности — фича `exchange-1c`. Экран «Оргструктура», заявки руководителей (16) — там же.
- Вкладки «Черновики из бота» и «Доступ к боту» — фича `bot`.
- Отправка писем кандидату системой: только черновик для копирования (Решения).
- Публикация вакансии на hh (17) — позже, отдельной задачей.
- Планировщик ночных задач и отправка по расписанию — фича `deploy`. До неё ночное применение и сводка запускаются командой `hr.cli run`.
- Доступ с телефона.
