# Пожелания руководителя отдела персонала к порталу — 10.11.2026

Пересказ PDF «Комментарии к ИИ» без персональных данных. Решений здесь нет: они — после анкеты
(`Анкета_по_пожеланиям_HR.md` в корне) и брейншторма.

## Что просят

1. **Карточка и реестр кандидата.** Подтягивать с hh комментарии к соискателю и статусы общения (отказали мы,
   отказался, не вышел на связь), историю откликов. Один человек делает много резюме на hh, и для hh новое резюме —
   «с чистого листа», поэтому сейчас каждый рекрутер ведёт свой реестр. Нужен общий реестр в портале, поиск по
   номеру телефона с полной историей: резюме, комментарии, статусы hh, был ли оформлен у нас и уволен (как в CRM
   подбора, которой пользовались раньше).
2. **Звонки и мессенджеры.** Сохранять звонки рекрутеров кандидату (корпоративные телефоны) и переписку из
   корпоративных MAX, WhatsApp, Telegram.
3. **Чат-бот.** Как ассистент hh: холодный поиск по критериям и рассылка откликов с просьбой связаться; на части
   вакансий — переписка с кандидатом, ответы на частые вопросы, обязательные вопросы и отсев по ответам.
4. **База должностей.** Менять ключевые слова без одобрения руководителя: отдел персонала — эксперт поиска,
   руководитель смотрит на позицию однобоко.
5. **Воронка.** Отслеживать этап общения (телефонное интервью, тестовое, собеседование), выгружать аналитику:
   конверсия по этапам, причины отказа. Воронка общая и настраиваемая (у кого-то есть тестовое задание).
   Образцы отчёта: по отделу — Резюме → Первичный контакт → Пройденное интервью → Интервью → Собеседование →
   Проверка СБ → Оффер → Пришедшие в 1 день; у рекрутера — то же по вакансии с датами открытия и закрытия, сроком
   ведения и общей конверсией.
6. **Мелочи.** Комментарий к статусу карточки — не 200, а 100 знаков. Добавить в блок «Резюме» строку «возраст»
   (список в PDF обрывается на ней).

## Что уже есть в портале (для сверки)

- Воронка с этапами: Отобран агентом, Написали, Ответил, Телефонное интервью, Встреча с руководителем, Тестовое
  задание, Проверка СБ, Оффер, Резерв; закрытия — вышел, отказали мы, отказался, не захотел общаться, не пришёл.
  Этапы фиксированные, выгрузки аналитики нет.
- Сшивка резюме одного человека по нику и похожести. Идентификатор соискателя hh (`owner.id`, общий для всех его
  резюме) пока не используется — `docs/reference/hh-api.md`, пункт 5 расхождений.
- Комментарии и отклики hh доступны по API (`/applicant_comments/{owner.id}`, `negotiations_history`), портал их
  не читает. Приглашение соискателя через API списывает платный контакт.
- Выгрузка сотрудников 1С приходит каждый день, но без дат приёма и увольнения.
- Правила проекта, которые затрагивают пожелания: действие с человеком только после подтверждения
  (`never.md`); комментарий от 200 знаков закреплён в схеме базы проверкой (`schema_recruiting.sql:529, 850`);
  контакты — только в зоне кандидата (AD-3); возраст, пол и семья не участвуют в отборе (ТК РФ ст. 3, 64).
