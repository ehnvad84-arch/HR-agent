## Зачем — главная сессия

Отдел персонала ищет людей, но лучше всех знает, кто нужен, начальник подразделения. Нужно: начальники подразделений со своим входом видят вакансии и подходящих людей только по своему подразделению, описывают требования к должностям подчинённых и передают понравившихся в отдел персонала; отдел персонала ведёт кандидата по воронке. Каждый пользователь учит агента под себя.

Брейншторм 2026-10-30 (office-hours), допущения 1–14 приняты человеком целиком:
1. Отдел персонала — все из «Отдела управления персоналом» по 1С: вся база, досье, вакансии, воронки, решения, контакты, загрузка резюме; его начальник — руководитель отдела персонала (утверждает портреты, сводку, настройки).
2. Руководитель — сотрудник с «Руководитель / Начальник / Директор» в должности (список правит руководитель отдела персонала); видит своё подразделение и всё вложенное.
3. Директор во главе «Основного подразделения» видит всю компанию как руководитель, без действий отдела персонала. Прочие сотрудники доступа не имеют.
4. Логин — из выгрузки сотрудников 1С; пароль задаётся при первом входе по одноразовому коду от отдела персонала.
5. Нужна выгрузка сотрудников 1С (логин, ФИО, подразделение, должность, работает); до неё руководитель отдела персонала заводит людей вручную; уволенный теряет доступ после выгрузки.
6. Руководитель видит вакансии своего поддерева; в «Сегодня» и «Базе» — только людей с баллом по должностям поддерева; досье с ФИО и фото, без контактов; каждый просмотр — в журнал.
7. Воронки руководитель видит только по своим вакансиям: этапы и заметки отдела персонала, без контактов.
8. Руководитель правит портреты должностей поддерева; общая должность — один портрет, правит любой руководитель, в чьём поддереве она есть; утверждает руководитель отдела персонала.
9. У руководителя нет решений по людям, открытия контактов и загрузки резюме.
10. «Передать в отдел персонала» — из «Сегодня», «Базы», досье, «Подходящих»; выбор открытой вакансии своего поддерева и комментарий, чем понравился; без открытой вакансии нельзя.
11. Передача приходит ответственному HR вакансии (назначается при создании), руководитель отдела персонала тоже видит; HR берёт в работу (контакт, воронка) или отклоняет с причиной, видной руководителю.
12. Личное обучение: свой чат замечаний → личные поправки весов и стоп-факторов → «мой балл» и порядок только для себя; общий балл не меняется.
13. Повторяющиеся у нескольких замечания агент выносит в недельную сводку; общими они становятся по решению руководителя отдела персонала.
14. Телеграм-бот руководителей убран из плана.

## Поведение (BDD) — главная сессия

«Поддерево» — подразделение руководителя и все вложенные (оргструктура 1С, `org_unit`). «Его должности» — должности 1С в поддереве и их портреты (`job_role_map`). «Отдел персонала» — роли `recruiter` и `head_recruiter`.

### Пользователи и вход

**S1: выгрузка сотрудников 1С.** Дано: файл сотрудников в обменном каталоге 1С (идентификатор, логин, ФИО, подразделение 1С, должность, работает). Когда: «Обновить из 1С» на экране «Доступ» или ежедневно. Тогда: новые заводятся, изменившиеся обновляются, уволенные теряют доступ и сессии; роль по правилу: «Отдел управления персоналом» — специалист, его руководитель — руководитель отдела персонала; должность с «Руководитель / Начальник / Директор» — руководитель; прочие — без доступа. Роль, правленную человеком, выгрузка не перетирает.

**S2: доступ вручную.** Дано: руководитель отдела персонала, экран «Доступ». Когда: заводит человека или меняет роль и подразделение. Тогда: изменение действует сразу и пишется в журнал изменений.

**S3: первый вход по коду.** Дано: отдел персонала выдал человеку одноразовый код (действует `invite_code_hours`). Когда: человек вводит логин и код, затем новый пароль (не короче 8). Тогда: пароль сохранён хешем, код погашен, человек вошёл. Код неверный, просрочен или уже использован — отказ без подсказки, что именно не так; пять ошибок подряд — блокировка как у пароля.

**S4: без доступа.** Дано: сотрудник без роли или уволенный. Когда: пытается войти или открыть API. Тогда: «Доступ не выдан, обратитесь в отдел персонала»; данных нет.

### Кабинет руководителя

**S5: граница видимости.** Дано: руководитель. Тогда: он видит только вакансии поддерева, людей с баллом по его должностям, их досье (с ФИО и фото, без контактов) и воронки своих вакансий. Чужая вакансия, человек или воронка — 404 от сервера, как будто их нет. Каждый просмотр досье — в `audit_log`.

**S6: «Сегодня» руководителя.** Дано: руководитель. Когда: открывает кабинет. Тогда: новые и изменившиеся люди выше порога по его должностям, открытые вакансии поддерева со счётчиком подходящих и судьба переданных им людей. Кнопок решений по людям, контактов и загрузки резюме нет.

**S7: «Мои вакансии».** Дано: открытая вакансия поддерева. Тогда: руководитель видит её ответственного HR, подходящих по убыванию балла и воронку (этапы и заметки отдела персонала, без контактов). Создать, изменить или закрыть вакансию он не может.

**S8: «Мои должности».** Дано: руководитель. Тогда: дерево должностей поддерева без повторов; правка портрета создаёт версию «ждёт утверждения» с его именем, выдача — по прежней до утверждения руководителем отдела персонала. Портрет должности вне поддерева править нельзя (403).

**S9: передать в отдел персонала.** Дано: человек из «Сегодня», «Базы», досье или подходящих. Когда: «Передать в отдел персонала», выбор открытой вакансии поддерева и комментарий «чем понравился» (не короче `handoff_comment_min`). Тогда: передача видна ответственному HR вакансии и руководителю отдела персонала в их «Сегодня», руководителю — со статусом «передан». Нет открытых вакансий — кнопка неактивна с объяснением. Тот же человек в ту же вакансию повторно — «уже передан».

**S10: судьба переданного.** Тогда: руководитель видит статус: передан → взят в работу (кто) → этап воронки → вышел / отказ с причиной; или «отклонён отделом персонала» с причиной.

### Отдел персонала

**S11: разбор передач.** Дано: передача в «Сегодня» специалиста. Когда: «Взять в работу». Тогда: человек становится кандидатом этой вакансии (как «Сохранить» сейчас: основание, контакт по кнопке с подтверждением). Когда: «Отклонить» с причиной (не короче `handoff_comment_min`). Тогда: руководитель видит причину.

**S12: вакансии и ответственные.** Тогда: вакансию заводит только отдел персонала; при создании обязательны ответственный HR и руководитель-заказчик (по умолчанию — руководитель подразделения должности).

**S13: загрузка резюме.** Тогда: кнопки загрузки hh у всех специалистов отдела персонала; у руководителей их нет, сервер отвечает 403.

### Личное обучение

**S14: свои замечания.** Дано: любой пользователь, «Обучение агента». Тогда: он видит только свой чат замечаний и ответы агента; чужих нет.

**S15: «мой балл».** Дано: пользователь задал личные поправки (ключевые слова плюс и минус, стоп-слова, веса признаков) вручную или подтвердил предложенные агентом по его замечаниям. Тогда: в его списках рядом с общим баллом — «мой балл», сортировка по нему; у других пользователей ничего не меняется; общий балл тот же.

**S16: из личного в общее.** Дано: одна и та же поправка у `shared_tweak_users` и больше пользователей. Тогда: агент выносит её в недельную сводку; по решению руководителя отдела персонала она становится версией портрета на утверждение.

### Справка

**S19: «Как работает портал» в «Схеме».** Дано: любой пользователь. Когда: открывает «Схему». Тогда: сверху — раздел «Как работает портал»: что он делает, роли и права (кто что видит и может), правила (утверждение портретов, комментарии от 200 знаков, контакты по подтверждению, лимиты hh), что портал умеет и чего не умеет; текст обновляется с каждым выпуском (правило conventions.md). Руководителю «Схема» доступна только в части справки, без хода задач.

### Проверка загрузок

**S20: итог каждой загрузки — отделу персонала.** Дано: прошла загрузка резюме по расписанию или кнопкой (hh, «Работа России», фото). Тогда: проверка разбирает итог и шлёт всем действующим сотрудникам отдела персонала сообщение в портал (колокольчик в шапке) и на почту, если она настроена: «Загрузка hh 30.10 18:00 прошла: просмотрено 412, новых 57, изменилось 12» — или тревогу «Загрузка не прошла — требуется разбирательство» с причиной простыми словами (ошибка площадки, лимит исчерпан, ключ hh истёк, проверка на робота, 0 резюме при обычной загрузке, больше `load_alarm_error_pct` % ошибок). Раз в час проверка ищет загрузки, которые не начались по расписанию или зависли дольше `load_stuck_hours`, — тоже тревога. Одна и та же тревога не повторяется чаще раза в `load_alarm_repeat_hours`. Тревога видна красной полосой у всех HR, пока кто-то не нажмёт «Разбираюсь» (с именем).

### Ошибки и границы

**S17: руководитель без подразделения.** Тогда: кабинет пуст с текстом «Подразделение не указано — обратитесь в отдел персонала».

**S18: смена подразделения или увольнение.** Тогда: с ближайшей выгрузки видимость пересчитывается; переданные им люди остаются у отдела персонала.

«Сегодня» руководителя — первая вкладка кабинета (снимает вопрос о допущении 6). Чужой объект (404) — карточка «Не найдено или нет доступа» и ссылка на «Сегодня»: причину не различаем.

**Вход (S3, S4).** `login.js`: под формой пароля кнопка-ссылка «У меня есть код». Она меняет форму на одну: «Логин» (`autocomplete="username"`), «Код из отдела персонала» (`one-time-code`), «Новый пароль» и «Повторите пароль» (`new-password`, «Не короче 8 знаков», кнопка «Показать» с `aria-pressed`), «Сохранить и войти»; обратно — «Войти по паролю». Ошибки: пароли не совпадают или короче 8 — у поля до отправки; код не подошёл по любой причине — «Логин или код не подходят. Код мог истечь — попросите новый в отдел персонала», поле кода очищается, логин остаётся; блокировка — текст как у пароля. Вход без роли или уволенного — страница «Доступ не выдан, обратитесь в отдел персонала» и «Выйти».

**«Доступ» (S1, S2, руководитель отдела персонала).** Над таблицей: «Обновить из 1С» и строка «Последняя выгрузка 30.10 06:00 · новых 3, изменено 5, уволено 1» (ошибка файла — `--red-tint` с текстом сервера); «Добавить вручную». Таблица `.tablewrap`: ФИО · Логин · Должность · Подразделение · Роль · Вход · действие; фильтры: поиск, роль, «только руководители». Роль — `.chip` текстом, у правленной вручную — `.chip.v` «вручную» (выгрузка не перетрёт). «Вход»: «входил 29.10» / «код до 31.10 14:00» / «не входил» / «уволен». Строка → окно «Доступ: ФИО»: роль, подразделение (список с отступами по дереву), подсказка «Действует сразу, запишется в журнал». «Выдать код» → окно с кодом моноширинным крупно, «Скопировать», «Действует до …», «Код виден один раз. Передайте человеку лично».

**«Сегодня» руководителя (S6, S17).** Без «Загрузить резюме». Блоки в прежнем виде `.zone`:
1. `z1` «Новые и изменившиеся — по вашим должностям»: карточка сигнала без кнопок решений; кнопки «Передать в отдел персонала» и «Досье».
2. `z4` «Открытые вакансии вашего подразделения»: название, подразделение, «Ответственный: Петрова А.», ссылка «Подходящих: 12».
3. `z2` «Кого вы передали»: имя, вакансия, бейдж статуса (S10), причина отказа текстом.

Пусто: «Новых людей по вашим должностям нет» и ссылка «Мои вакансии». S17 — на всех вкладках кабинета одна карточка «Подразделение не указано — обратитесь в отдел персонала».

**«Мои вакансии» (S7).** Карточки вакансий поддерева без «Новая вакансия» и «Закрыть»: название, подразделение, ставки, срок, «Ответственный HR», «Заказчик». Вакансия → `.split`: слева «Подходящие» по убыванию балла (по «моему баллу», если он есть) с фото, именем, баллом, «Передать» или бейджем статуса; справа воронка только для чтения: этапы, имена, заметки отдела персонала, без перетаскивания, «Перевести» и контактов. Пусто: «Открытых вакансий нет. Вакансию заводит отдел персонала».

**«Мои должности» (S8).** Экран `profiles` с деревом только поддерева. Кнопка «Отправить на утверждение» вместо «Сохранить как новую версию», без «Утвердить». Статусы: `.chip.g` «утверждён», `.chip.o` «ждёт утверждения — правка ФИО от 30.10». Для общей должности над формой `.note` «Должность есть и в других подразделениях: правка меняет общий портрет». Под кнопкой: «До утверждения балл считается по прежней версии». У руководителя отдела персонала в «Базе должностей» у такой версии — автор, «Утвердить» как сейчас. 403 — «Эту должность править нельзя: она не в вашем подразделении».

**«База» и досье руководителя (S5).** Таблица `base` с теми же колонками, фильтр должностей — только его; в строке — «Передать». Досье: ФИО, фото, балл, разбор, история; нет кнопок решений, блока «Контакты», «Выгрузить досье», ссылок на резюме площадки и профили в сети. Главная кнопка — «Передать в отдел персонала», ниже блок «Передачи» со статусами. Под заголовком подсказка «Просмотр записан в журнал доступа».

**Окно «Передать в отдел персонала» (S9).** Кнопка — в карточке «Сегодня», строке «Базы», досье, строке «Подходящих». `.sheet` «Передать: имя»: «Вакансия» — радиокнопки (больше пяти — список) открытых вакансий поддерева, сверху те, где у человека есть балл, с баллом; уже переданная — неактивна с пометкой «уже передан». Под выбором — «Получит: Петрова А., ответственный HR». «Чем понравился» — `textarea` со счётчиком как у окна комментария: «Ещё 54 знака» → «✓ достаточно», порог `handoff_comment_min` из ответа API. «Передать» неактивна, пока нет вакансии и текста. Успех — окно закрывается, уведомление «Передано Петровой А.», на месте кнопки — бейдж «передан». 409 — «Уже передан в эту вакансию» в окне. Открытых вакансий нет — кнопка с `aria-disabled="true"` (остаётся в фокусе) и подписью «Нет открытых вакансий — передать некуда».

**Бейджи статуса (S10).** `.chip.b` «передан 30.10» → `.chip.g` «в работе у Петровой А.» → `.chip.v` «этап: собеседование» → `.chip.g` «вышел на работу» или `.chip.r` «отказ»; `.chip.r` «отклонён отделом персонала». Причина — строкой под бейджем, как текст.

**Отдел персонала (S11–S13).** В «Сегодня» первым блоком — новый `.zone.z5` (`--violet-tint`, рамка `--violet-ink`: токены есть, нужен только класс) «Передали руководители — решите, брать ли в работу», остальные блоки нумеруются 2–5. Карточка: фото, имя (ссылка на досье), балл по вакансии, «Вакансия: …», «Передал: Иванов И. И., начальник ОГМ · 30.10 09:12», комментарий цитатой. ## Безопасность — backend-architect

<!-- Какие данные и секреты затронуты · точки входа · аутентификация и права ·
модель угроз AI-компонентов по MITRE ATLAS, если он применим (см. docs/rules/security.md). -->

**Данные и секреты.** Новые персональные данные сотрудников компании (логин, ФИО, подразделение, должность, почта) из выгрузки 1С; ФИО и фото кандидатов теперь видят руководители (решение человека, уточнение AD-3). Новых секретов нет: хеш кода — HMAC от `SESSION_KEY`. Файл выгрузки и коды в логи не пишутся, в журнал — только счётчики.

**Точки входа.** Новый открытый маршрут — `POST /api/login/code` (проверка `Origin`, как `/api/login`). Остальные — за `require`/`require_scoped` с CSRF. Файл сотрудников — из `EXCHANGE_1C_DIR` или загрузкой ≤ 5 МБ, JSON, имя файла в путь не идёт.

| # | Угроза | Меры | Тест |
|---|---|---|---|
| M1 | Руководитель читает чужое: подставляет `person_id`, `vacancy_id`, `fit`, `profile_id` | скоуп только на сервере, одна функция `scope.for_user`; 404 вне скоупа неотличим от «нет»; тест требует `require_scoped` у всех маршрутов `base.read` | руководитель A открывает человека, вакансию, воронку, профиль B → 404 по каждой точке из таблицы выше |
| M2 | Руководитель выходит на контакт в обход HR | нет `contact.open`, `dossier.export`, `person.take`; из досье убраны ссылки на резюме площадки и профили в сети; телефоны и почта в заметках и комментариях маскируются | ответ досье и воронки руководителю не содержит `url`, телефона, почты |
| M3 | Перебор одноразовых кодов | код 10 знаков из 32 (≈ 50 бит), в базе HMAC; срок `invite_code_hours`; блокировка после `login_max_failures` на `login_lock_minutes`, как у пароля (`auth.py:156`); один ответ на неверный, истёкший, погашенный код и неизвестный логин | 6-я попытка → 429; погашенный код → тот же 401 |
| M4 | Захват чужой учётки через выдачу кода | специалист выдаёт код только руководителям и директору без пароля; сброс для HR и уже входивших — только `access.manage`; выдача — в `audit_log` (`action = 'invite'`); код показывается один раз, по почте и в Telegram не уходит | recruiter → код для head_recruiter → 403 |
| M5 | Уволенный или лишённый роли остаётся в системе | выгрузка: `is_active = false`, отзыв сессий и кодов; `load_session` отказывает неактивному и роли без прав; права читаются на каждый запрос (`auth.py:92`) | уволенный в выгрузке → следующий запрос 401 |
| M6 | Подмена файла сотрудников раздаёт роли | файл только из обменного каталога или от `access.manage`; отказ при пропаже > `users_max_drop_pct`; роль `agent` выгрузка не назначает и не трогает, роль из `ops.user_override` — тоже; все изменения ролей — `agent_change`, в недельный отчёт | файл с пропажей 30 % → ничего не применено |
| M7 | Утечка ФИО через журнал и поиск | просмотр досье руководителем и директором — `audit_log`, без исключений; поиск `q` не пишется в журнал доступа (workplace) | открытие досье → строка `view` |

**Модель угроз AI (MITRE ATLAS).** Новое: модель предлагает личные поправки по замечаниям пользователя; повторы уходят в сводку. Инструментов и права действовать у модели нет, W1–W6 из workplace действуют.

## Решения — главная сессия

| Вопрос | Выбрано | Почему | Отвергнуто |
|---|---|---|---|
| Вход руководителей | логин из 1С, свой пароль по одноразовому коду | пароли из 1С не выгружаются; работает без 1С-специалистов | единый вход через 1С — позже; ручное заведение — только до выгрузки |
| Граница видимости | своё подразделение и всё вложенное | начальник департамента отвечает за отделы | только своё |
| Какую базу видит руководитель | людей с баллом по должностям своего поддерева | ответ человека | вся база (как в ТЗ 10); только под открытые вакансии |
| Кто заводит вакансии | только отдел персонала | ответ человека | заявка руководителя в портале; только из 1С |
| Требования руководителя | новая версия портрета, утверждает руководитель отдела персонала | балл всей базы меняется только после проверки | сразу без утверждения |
| Должность в нескольких отделах | один портрет | один балл, без 8-кратного счёта | свой портрет у каждого отдела; правит только общий начальник |
| Обучение | личный слой + общее через сводку | ответ человека | только тексты |
| «Сегодня» руководителя | только должности его поддерева | ответ человека | «Мои вакансии» вместо «Сегодня» |
| ФИО у руководителя | видит, как HR; просмотры в журнале | ответ человека | только ярлык (AD-3) → architecture.md: уточнить AD-3 |
| Получатель передачи | ответственный HR вакансии + видит руководитель отдела персонала | ответ человека | общая очередь |
| Загрузка резюме | все специалисты отдела персонала | ответ человека | только руководитель отдела персонала |
| Начальники | по должности + правка HR | без 1С-доработок | вручную; поле из 1С |
| Бот | не нужен → убрать фичу bot из PRD | ответ человека | бот позже |
| Форма | отдельный кабинет руководителя («Мои вакансии → подходящие → передать», «Мои должности») | выбор человека | роли поверх общих экранов; минимальный вариант |
| Видимость по оргструктуре (backend-architect) | одна функция `scope.for_user` на сервере, маршруты `base.read` — только через `require_scoped`, вне скоупа — 404 → architecture.md | одна точка проверки, тест ловит забытый маршрут | фильтры в каждом запросе по месту; скрытие в интерфейсе |
| «Без доступа» (backend-architect) | значение `no_access` в `user_role` миграцией | «уволен» и «не выдан» различимы | `is_active = false`; отдельная таблица допуска |
| «Мой балл» (backend-architect) | кэш `ops.user_match`, пересчёт в фоне | сортировка по всей выдаче (S15) | расчёт на лету для страницы |

| Мелкие правила (Гейт 1, человек) | ссылки на резюме и профили в сети руководителю не отдаются; руководитель отдела персонала разбирает любые передачи; один набор личных поправок на все должности; отклонённого в ту же вакансию повторно не передать; `handoff_comment_min` 50, `invite_code_hours` 72, `shared_tweak_users` 3; подразделение — всегда из 1С, ручная роль сохраняется; заместителей правят вручную | ответ человека 2026-10-30 | — |
