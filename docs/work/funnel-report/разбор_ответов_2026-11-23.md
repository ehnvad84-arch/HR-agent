# Разбор ответов руководителя отдела персонала и образца отчёта — 23.11.2026

Источники: `ответы_ОП_2026-11-23.json` (анкета `Анкета_воронка.html`), образец «Отчётность с 2026.xlsx» — в репозиторий
не кладётся: на листах адаптации ФИО сотрудников. Здесь только устройство файла.

## Как устроен их отчёт (Excel)

- **Лист на рекрутера за год** («<Имя> 2026»): сверху «Общая воронка» рекрутера = сумма его вакансий; ниже — блок на
  каждую вакансию: название, «Дата открытия», «Дата закрытия», «Срок ведения вакансии» = `DAYS(закрытие, открытие)`
  (открытая — до `TODAY()`).
- **Блок воронки — 8 строк, всегда одни и те же:** Отобранные резюме → Первичный контакт → Пройденное первичное
  интервью → Интервью → Собеседование → Проверка СБ → Оффер → Пришедшие в 1 день.
- **Столбцы блока:** «Количество соискателей» (вошли) · «Конверсия этапа в шт» (прошли) · «Конверсия этапа в %».
  «Вошли» этапа = «прошли» предыдущего. Внизу «Конверсия воронки» = пришедшие в 1 день / отобранные резюме.
- **Лист «Метрики»:** «Воронка подбора 2026» = сумма общих воронок рекрутеров; рядом — адаптация, ССЧ, текучесть
  (это не воронка — к фиче `history-1c`); «Принятые вне воронки» (рефералы, от руководства, без подбора) — счётчик.
- Периода «месяц» в воронке нет: год, рекрутер, вакансия.

## Ответы (коротко)

| Тема | Ответ |
|---|---|
| Кто и зачем | руководитель ОП — каждую неделю ищет просадку конверсии и её причину; рекрутеры — свои вакансии постоянно, «для рефлексии» |
| Период | не месяц: вакансия, срок — в календарных днях |
| Этапы | «Пройденное интервью»: проведено телефонных / прошли успешно; «Интервью»: приглашены на собеседование / прошли; «Собеседование»: пришли / прошли. «Прошёл» = положительная резолюция рекрутера, на собеседовании — руководителя |
| Портал сейчас | «организован неверно»: нет «вошли/прошли» по каждому этапу (СБ: зашли / прошли; оффер: выставлен / принят / вышел) |
| Пропуски и возвраты | не бывает: только вперёд или отказ |
| Этапы вакансии | одна обширная библиотека этапов, из неё собирают набор под вакансию (4 собеседования с разными руководителями, тестовое, оплачиваемое тестовое); рекрутер предлагает, руководитель ОП утверждает |
| Причины отказа | отказали мы: опыт/навыки, тестовое, СБ; отказался сам: «не подходят условия труда» (зарплата+график+место), «отказ от оффера» (другое предложение+передумал); не вышел на связь; не пришёл на встречу; не вышел в первый день |
| «Вышел в 1 день» | отмечает рекрутер в портале |
| Испытательный срок | позже |
| Срок вакансии | с дня заведения в портале; паузы не считаются |
| Норма срока | нет; ориентир — 1 месяц, зависит от загрузки, сезона (декабрь, март, август), уровня позиции |
| Разрезы / графики | вакансии, рекрутеры / воронка по этапам, конверсия этапов по рекрутерам |
| Старые данные | с чистого листа |
| Обязательно к концу ноября | настройка этапов под вакансию — иначе рекрутеры остаются в Excel |
| Опасение | система выдумает свои этапы, не будет честно считать, сломает методику «в угоду ИИ» |

## Что из этого следует для фичи

1. Воронку считает код по отметкам рекрутера, без модели и без этапов, придуманных агентом (AD-2; опасение ОП).
2. У каждого этапа — исход: прошёл / не прошёл (+ причина). Без этого «вошли → прошли» не посчитать.
3. Этапы вакансии — из одной библиотеки; каждый этап библиотеки относится к одной из 8 строк отчёта, чтобы отчёт
   оставался в их форме, даже если собеседований четыре.
4. Выгрузка Excel — по образцу: лист на рекрутера, общая воронка + блоки вакансий, 3 столбца, срок ведения в днях.
5. Норм срока, месяцев, испытательного срока и адаптации в этой фиче нет.
