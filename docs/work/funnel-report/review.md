## Отдельные оценки по запросу

**(1) Известные дефекты T15.**
- Отказ нельзя отменить после ухода с доски, см. находку 1, **blocker**. Как это ломает работу:
  - Рекрутер ошибся кандидатом или причиной, затем обновил страницу или ушёл с экрана. После этого отметку не отменит никто из интерфейса, даже руководитель ОП.
  - Кандидат выпал из воронки, а в отчёте навсегда лишний отказ на этой строке.
  - То же для «Вышел в первый день», пока вакансия открыта, и для любого «Закрыть» на «Сегодня»: там кнопки отмены нет совсем.
  - Обойти можно только curl с cookie и CSRF или SQL, а SQL нарушает AD-1.
  - ОП боится именно нечестного счёта, а ошибки в первые недели на новом окне вероятны.
- «В резерв» на «Сегодня», см. находку 3, **major**. В v1.2.0 кнопка работала, теперь у перенесённых и новых зависших почти всегда 409. Данные не портятся, но это регрессия на главном экране.

**(2) Допущения, меняющие поведение.**
- T4, производный статус по последнему действию в любой вакансии: при нескольких вакансиях врут счётчик «в работе» и «Зависли» (находка 6, minor). Карта статусов разумна для отката.
- T6, «Отобраны агентом» = новые сигналы по должности вакансии: разумно, в отчёт не входят, вход только кнопкой человека. Руководителю подразделения блок тоже приходит; ФИО ему разрешены по AD-3, кнопка скрыта.
- T8, «вошли» по диапазону строк: совпадает со спекой при неизменном наборе и лучше спеки, когда строку добавили посреди хода. Но спека — источник правды, её текст нужно обновить (находка 4, minor).
- T10, рекрутер отмечает итоги в чужой вакансии и этим меняет чужой отчёт. Спека этого не запрещает, в `decided_by` видно, кто отметил. Нужно решение человека (находка 8, minor).
- T12, дата встречи через `mark`: отмена не убирает встречу (находка 5, minor).

**(3) Миграция 012 и AD-8.**
- Только добавляет, линтер DDL зелёный, v1.2.0 на новой базе зелёная (687).
- `ops.funnel_carry()` детерминирована (SQL без модели). Повтор ничего не меняет, это покрыто тестом. Вызывают её миграция и `hr.cli funnel-carry`.
- Ограничения при возврате после отката: пары с отметками не сверяются (в CHANGELOG описано); пауза, закрытая в v1.2.0, остаётся открытой в `ops.vacancy_pause` (находка 9, в CHANGELOG не описано).

**(4) Модель в счёте не участвует.**
- `stages.py`, `funnel_report.py`, `api/stages.py` импортируют только `db`/`auth`/`scope`. В `ops.candidate_stage`/`stage_set` пишут только `stages.py` и `vacancies.py`.
- Вызывают их только маршруты с правами `person.take`, `vacancy.edit` или `stage.approve`, у роли `agent` этих прав нет (тесты `test_agent_writes_no_stages`, `test_movement_needs_rights`). Фоновые задачи (`tasks`, `collect`, `alerts`, `llm`) этих таблиц не трогают.
- Одобренное письмо меняет только статус. Единственный автоматический выбор: «Взять в работу» без явной вакансии ставит человека в вакансию с лучшим баллом (`decisions.py:60`). Балл считает код (AD-2), это не модель, и так было и до фичи; теперь это влияет на «Отобранные резюме» (находка 11, minor).
