# Список изменений портала «Рувер»

Новая версия — раздел сверху. В каждом разделе пять подразделов: что нового, миграции, переменные `.env`, ручные
шаги, можно ли откатиться. Как обновляться — `ОБНОВЛЕНИЕ_портала.md`.

## v1.1.0 — 2026-11-10

### Что нового

- У портала есть номер версии: `python -m hr.cli version`, строка внизу «Схемы» → «Как работает портал».
- Обновление одной командой `scripts/update.sh vX.Y.Z`: проверки до остановки, копия базы, миграции, запуск и
  проверка; при неудаче портал сам возвращается на прежнюю версию.
- Откат на прошлую версию — `scripts/rollback.sh vX.Y.Z`, без изменения базы.
- Одна свежая копия базы: `scripts/db_copy.sh` перед миграциями и по недельному таймеру.
- Новое умолчание настройки не перетирает значение, которое поменяли в портале: в итоге обновления — «настройка …
  оставлена как есть».

### Миграции

- `009_release.sql` — журнал версий `ops.release`, заметки обновления `ops.release_notice`, функция
  `ops.change_default`. Только добавляет.

### Переменные .env

Новых нет. Настройки обновления — в `server/update.conf` (образец `server/update.conf.example`), это не `.env`.

### Ручные шаги

- Первый раз: установка из архива становится копией репозитория — раздел «Первый раз» в `ОБНОВЛЕНИЕ_портала.md`;
  ключ GitHub только на чтение (deploy key) выдаёт владелец репозитория.
- `server/update.conf` по образцу: команды остановки и запуска служб, каталог копии базы вне репозитория.
- Недельный таймер копии базы — по образцу из `server/update.conf.example`.

### Откат

нет — ниже v1.1.0 `rollback.sh` не откатывает: у v1.0.0 нет журнала версий. Если обновление с v1.0.0 не удалось,
`update.sh` сам возвращает v1.0.0.
