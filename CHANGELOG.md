# Список изменений портала «Рувер»

Новая версия — раздел сверху. В каждом разделе пять подразделов: что нового, миграции, переменные `.env`, ручные
шаги, можно ли откатиться. Как обновляться — `ОБНОВЛЕНИЕ_портала.md`.

## v1.2.0 — 2026-11-22

### Что нового

- **Синонимы ключей.** В «Базе должностей» у ключевых слов профиля — синонимы: «Предложить синонимы» (модель
  подбирает, рекрутер правит), «Сохранить синонимы» — действуют сразу, без утверждения версии, с журналом и
  откатом последней правки. Ключ засчитывается по синониму («Altium ≈ P-CAD»), синонимы расширяют запрос к hh
  (не больше 20 терминов). Правят рекрутер и руководитель отдела персонала (право `profile.synonyms`),
  руководители подразделений только видят.
- **Близость по смыслу.** Новый признак балла «Близость по смыслу» (вес 15): векторы bge-m3 резюме и профиля,
  подпись «близко к профилю по смыслу: 82 %». Нет вектора или служба недоступна — признак «не учтено» и вне
  суммы, балл как раньше. Поиск в «Базе» — тоже bge-m3, запрос до 300 знаков.
- **Ночной пересчёт векторов** — задача `reembed_night` в 02:30 по Москве, по частям до 06:30; в «Схеме» —
  сколько резюме осталось.
- **Суточные пределы.** Полных резюме hh — не больше 300 в сутки на все сборы (остальные — завтра); запросов
  к модели — 500 в сутки, на синонимы — свои 100. Плитки «Полных резюме hh сегодня» и «Запросов к модели
  сегодня», предупреждения в «Схеме».
- **Флаг `llm_assist_enabled`.** Выключен — объяснения балла, черновики и разбор замечаний по шаблону, без
  модели; синонимы работают. Правится командой `python -m hr.cli setting set <ключ> <значение> --by <логин>`
  с записью в журнал изменений.
- Обход hh начинается каждый день с другой должности, чтобы первые должности не забирали весь предел.
- Исправлено: балл при входе в базу и после пересчёта совпадает, когда должность профиля есть только в опыте.

### Миграции

- `010_semantic_search.sql` — таблицы `role_synonym`, `ops.profile_embedding`, `ops.daily_quota`,
  `ops.service_health`; право `profile.synonyms` рекрутеру и руководителю отдела персонала; десять новых
  настроек через `ops.change_default`. Только добавляет. В `public` теперь 47 таблиц.

### Переменные .env

- `EMBED_BASE_URL=http://127.0.0.1:<порт>/v1` — служба bge-m3 на сервере портала (раздел 7 `ОБНОВЛЕНИЕ_портала.md`).
- `EMBED_MODEL=BAAI/bge-m3`.
- `EMBED_TIMEOUT_S` — новая, таймаут запроса к службе векторов в секундах; пусто — 60.
- `LLM_BASE_URL=http://10.20.10.6:11434/v1`, `LLM_MODEL=t-lite:2.1`, `LLM_API_KEY` — пусто или `ollama`.

### Ручные шаги

- До обновления: служба bge-m3 (text-embeddings-inference, CPU-образ по digest, порт только 127.0.0.1) и
  проверка образа как новой зависимости — раздел 7.1–7.2 `ОБНОВЛЕНИЕ_портала.md`.
- Строки `.env` выше, затем перезапуск портала.
- Перезапустить `bash server/scripts/install_autostart.sh` (или добавить свой таймер): появится таймер
  `ruware-reembed-night.timer` (02:30). В `server/update.conf` добавить его в `TIMERS`.
- После обновления: `python -m hr.cli hh-selftest`, проверка «Схемы», утром после первой ночи — сколько
  резюме пересчитано (раздел 7.5).

### Откат

да — на v1.1.0 через `rollback.sh v1.1.0`: новые таблицы старая версия не читает, вес `semantic` отбрасывает.
После отката не действуют синонимы, близость по смыслу и суточные пределы — остаются пределы за прогон.
Таймер `ruware-reembed-night` после отката выключить: `systemctl --user disable --now ruware-reembed-night.timer`.

## v1.1.0 — 2026-11-10

### Что нового

- У портала есть номер версии: `python -m hr.cli version`, строка внизу «Схемы» → «Как работает портал».
- Обновление одной командой `scripts/update.sh vX.Y.Z`: проверки до остановки, копия базы, миграции, запуск и
  проверка; при неудаче портал сам возвращается на прежнюю версию.
- Откат на прошлую версию — `scripts/rollback.sh vX.Y.Z`, без изменения базы.
- Одна свежая копия базы: `scripts/db_copy.sh` перед миграциями и по недельному таймеру.
- Новое умолчание настройки не перетирает значение, которое поменяли в портале: в итоге обновления — «настройка …
  оставлена как есть».

### Миграции

- `009_release.sql` — журнал версий `ops.release`, заметки обновления `ops.release_notice`, функция
  `ops.change_default`. Только добавляет.

### Переменные .env

Новых нет. Настройки обновления — в `server/update.conf` (образец `server/update.conf.example`), это не `.env`.

### Ручные шаги

- Первый раз: установка из архива становится копией репозитория — раздел «Первый раз» в `ОБНОВЛЕНИЕ_портала.md`;
  ключ GitHub только на чтение (deploy key) выдаёт владелец репозитория.
- `server/update.conf` по образцу: команды остановки и запуска служб, каталог копии базы вне репозитория.
- Недельный таймер копии базы — по образцу из `server/update.conf.example`.

### Откат

нет — ниже v1.1.0 `rollback.sh` не откатывает: у v1.0.0 нет журнала версий. Если обновление с v1.0.0 не удалось,
`update.sh` сам возвращает v1.0.0.
