# Установка портала подбора «Рувер» на свой сервер

Для инженера, который разворачивает портал на другом сервере компании. Версия от 30.10.2026.
Подробное ТЗ — `ТЗ_для_инженеров_развёртывание.md`; здесь — короткий путь, проверенный на пробном сервере.

## 1. Что нужно

- Linux (Ubuntu 22.04/24.04 или аналог), 4 ядра, 8 ГБ памяти, 100 ГБ диска.
- Python 3.12 и `uv` (`curl -LsSf https://astral.sh/uv/install.sh | sh`).
- PostgreSQL 16 с расширениями **pgvector** и **pg_trgm**. Проще всего — Docker:
  `docker run -d --name ruware-pg -p 127.0.0.1:5432:5432 -e POSTGRES_PASSWORD=<пароль> pgvector/pgvector:pg16`.
- Наружу открыт только SSH. Портал слушает `127.0.0.1:8000`, сотрудники открывают его через SSH-туннель
  (раздел 6).

## 2. Код и зависимости

```bash
unzip ruware-hr-<дата>.zip -d ~/projects && cd ~/projects/HR-agent/server
uv venv -p 3.12 .venv && uv pip install -r requirements.txt
```

## 3. Настройки (.env)

```bash
cp .env.example .env && chmod 600 .env && nano .env
```

Обязательно: `DATABASE_URL`, `SECRETS_KEY` (`.venv/bin/python -m hr.cli gen-key`), `SESSION_KEY`
(длинная случайная строка: `openssl rand -hex 32`), `WEB_HOSTS=localhost,127.0.0.1`,
`EXCHANGE_1C_DIR` (обменный каталог 1С). По желанию: `HH_*` (приложение работодателя hh), `GIGACHAT_*`
(языковая модель), `SMTP_*` и `MAIL_TO` (почта), `FEEDBACK_TG_TOKEN` и `FEEDBACK_TG_CHAT` (Телеграм-бот для
недельной сводки замечаний). Проверка без вывода значений: `.venv/bin/python scripts/check_env.py`.

Ключи и пароли в `.env` не пересылаются в чатах и не кладутся в архивы.

## 4. База и первый пользователь

```bash
set -a; . ./.env; set +a
.venv/bin/python -m hr.cli migrate                      # схема и все миграции
.venv/bin/python -m hr.cli user-create <логин> --name "<ФИО>" --role head_recruiter   # пароль спросит дважды
```

Дальше людей заводят в портале: «Доступ» → «Обновить из 1С» (файл `employees_*.json`, описание —
`docs/1c/выгрузка_сотрудников.md`) или «Добавить вручную», затем «Выдать код».

Оргструктура: положите отчёт 1С «Организационная структура» (JSON) в `EXCHANGE_1C_DIR` и нажмите
«Обновить из 1С» в «Базе должностей». Должностные инструкции прикрепляются к портретам в карточке
должности.

## 4а. Перенос рабочей базы из полного архива

В полном архиве лежат `перенос/ruware_hr.dump` (копия рабочей базы со всеми резюме), `перенос/server.env`
(файл `.env` пробного сервера), `перенос/data/` (файлы должностных инструкций и выгрузки 1С) и архив
должностных инструкций. Вместо шага 4:

```bash
createdb ruware_hr                                    # пустая база на новом сервере
pg_restore --no-owner -d ruware_hr перенос/ruware_hr.dump
cp перенос/server.env server/.env && chmod 600 server/.env   # затем поправьте DATABASE_URL под новый сервер
cp -r перенос/data server/data
.venv/bin/python -m hr.cli migrate                    # доведёт схему до версии кода, если она новее
```

Ключи hh в `.env` от пробного сервера: после переезда выпустите в кабинете hh новый Client Secret и пройдите
`hh-auth` заново (раздел 7). Новый `SESSION_KEY` — `openssl rand -hex 32`: старые сессии перестанут
действовать, все войдут заново. Архив содержит персональные данные кандидатов: храните его только в
закрытом месте и удалите копии после переноса.

## 5. Автозапуск

Скрипт ставит службы systemd пользователя: базу (если она локальная, путь в начале скрипта), портал и
таймеры — выгрузка сотрудников 1С в 06:10, сбор hh в 18:00, «Работа России» ночью с понедельника на
вторник, проверка загрузок раз в час, сводка замечаний по пятницам в 18:30.

```bash
nano scripts/install_autostart.sh   # проверьте пути APP, PG, DATA и DATABASE_URL в начале
bash scripts/install_autostart.sh
```

## 6. Доступ сотрудников

У каждого сотрудника — свой SSH-ключ в `~/.ssh/authorized_keys` с ограничением:
`restrict,port-forwarding,permitopen="127.0.0.1:8000",command="/bin/false" ssh-ed25519 AAAA… имя`.
На Windows ярлык запускает туннель скрыто: `ssh -N -L 18080:127.0.0.1:8000 <пользователь>@<сервер>`, затем
браузер открывает `http://localhost:18080`. Образец ярлыка — в мануале рекрутера, раздел 1.

## 7. hh.ru

`.venv/bin/python -m hr.cli hh-auth` — ссылка входа работодателя; после входа —
`.venv/bin/python -m hr.cli hh-selftest`. Адрес возврата в настройках приложения hh:
`http://localhost:8000/api/oauth/hh/callback`.

## 8. Проверка

```bash
DATABASE_URL=postgresql://…/ruware_hr_test .venv/bin/pytest -q   # имя базы обязано оканчиваться на _test
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/  # 200
```

Откройте портал, войдите, посмотрите «Схему» → «Как работает портал».
